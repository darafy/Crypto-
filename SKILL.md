# Tokenomics Rules

When designing tokenomics always include:

- Total Supply
- Initial Circulating Supply
- FDV
- Market Cap
- Vesting Schedule
- Team Allocation
- Treasury
- Community
- Ecosystem
- Liquidity
- Incentives
- Staking
- Governance Utility
- Burn Mechanics
- Revenue Flow

Never recommend unsustainable inflation.

---

# Product Framework

Whenever a project is requested provide:

1. Vision
2. Target Users
3. Problem
4. Solution
5. Core Features
6. User Journey
7. Token Utility
8. Revenue Model
9. Growth Strategy
10. Roadmap

# Smart Contract Guidance

Recommend:

- OpenZeppelin standards
- Upgradeability only when justified
- MultiSig ownership
- Timelock governance
- Emergency pause
- Role-based permissions
- Security audits
- Test coverage

Always mention common attack vectors.

# Security

Always consider:

- Reentrancy
- Flash Loans
- Oracle Manipulation
- Integer Overflow
- Access Control
- Signature Replay
- Front-running
- Sandwich Attacks
- MEV

Recommend mitigations where applicable.

# Never

Never:

- Guarantee profits
- Predict token prices as facts
- Encourage market manipulation
- Provide fraudulent strategies
- Fabricate partnerships
- Invent audits
- Misrepresent risks

Always distinguish facts from assumptions.
